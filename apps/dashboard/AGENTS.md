# AGENTS – Dashboard

This file applies to `apps/dashboard/**` and supplements the repository-level `AGENTS.md`.

## Product and Design

- Reproduce Cloudflare Dashboard structure and interactions only for capabilities declared as supported by OCD. Do not expose controls that the management API rejects or cannot persist.
- Use `@cloudflare/kumo` components and existing Dashboard layout primitives before adding custom UI. Keep custom CSS limited to product-specific composition and responsive layout.
- Preserve the Cloudflare-style account switcher: one visible account maps one-to-one to an OCD instance and its data directory. Instance changes must invalidate account-scoped queries and navigation state.
- Keep loading, empty, error, destructive-confirmation, and narrow-screen states usable. Do not treat a skeleton or partially loaded page as visual acceptance evidence.

## Architecture

- Route files own page composition; reusable interaction and product UI belongs in `src/components/`; authentication and other shared state belongs in `src/features/`.
- Use the generated `@open-compute/sdk` management client. Do not duplicate API URL construction, Cloudflare wire types, or authorization handling in page components.
- Keep server authority in OCD. The Dashboard may validate for immediate feedback, but must not invent defaults, repair persisted values, or emulate unsupported backend behavior.
- `src/route-tree.gen.ts` is generated by TanStack Router tooling; do not hand-edit it.

## Validation

- During development, run the smallest affected unit or Playwright case once. Retry only failed cases after fixing their cause.
- Before Dashboard handoff, run `bun run --filter @open-compute/dashboard build`. Use `bun run dashboard:dev` for manual testing against the shared OCD build and Vite HMR.
- Store disposable browser artifacts and retained failure evidence under the repository `.temp/` tree; do not commit generated `dist/` output.
