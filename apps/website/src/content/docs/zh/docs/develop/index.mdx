title: "开发应用"
description: "官方 cf、应用构建、目标选择与 CI。"
---

每个应用使用 `cloudflare.config.ts`、官方 Vite 插件 v2 和本地 cf。Bun 管理依赖，Node.js 22.18+ 执行 cf。类型生成与构建见[入门](/zh/docs/get-started/)。

```sh
bun install --frozen-lockfile
bun run dev
bun run build
ocd cf --target staging deploy --prebuilt --mode staging
```

`cf dev` 使用官方本地模拟资源。`ocd cf` 选择真实 OCD authority、注入目标凭据并透传 argv、输出、信号和退出码；不自动安装或升级工具。内部 CI 固定 `cf@1.0.0-beta.21`，用户可自行选择版本：非 `1.0.x` 只警告，仍允许执行。

| 概念     | 含义                                       | 选择方式                  |
| -------- | ------------------------------------------ | ------------------------- |
| instance | 本机注册的独立数据 authority               | `--instance` / `--config` |
| target   | 已保存的 API origin、账号和 token 文件引用 | `ocd cf --target`         |
| mode     | 官方配置回调中的应用模式                   | `cf --mode`               |

target 与 mode 独立；launcher 不把 target 名称当作 mode，不替用户合并配置或资源 ID。

```sh
ocd cf --project /srv/workers/billing --target production deploy --prebuilt --mode production
```

先显式执行官方 `cf migrate ./wrangler.jsonc --bundler vite` 迁移旧项目，完成 TODO 并安装构建插件。没有新配置时，wrapper 在读取凭据或联系目标前报错；help、资源命令和有效 prebuilt 路径不受旧文件影响。

日志使用 Dashboard Live Tail；cf 暂无等价终端流式入口。资源与 secrets 使用官方命令，运行 `cf cli search` 和命令 help 确认参数。不可把 secret 值放进 argv、日志或仓库。

CI 使用 frozen lock 安装，先无部署凭据严格 typecheck/build，再给 `cf deploy --prebuilt` 注入 `CLOUDFLARE_API_BASE_URL`、`CLOUDFLARE_ACCOUNT_ID` 和 `CLOUDFLARE_API_TOKEN`，并设置 `CF_SEND_TELEMETRY=false`、`DO_NOT_TRACK=1`。cf deploy 不会替用户运行 package build script；prebuilt 也不是不可信代码沙箱。

npm 用户可用 `npm install` 和 `npm run dev/build`；pnpm 用户可用 `pnpm install --frozen-lockfile` 和 `pnpm run dev/build`。安装开发依赖分别用 `npm install --save-dev` / `pnpm add -D`。
