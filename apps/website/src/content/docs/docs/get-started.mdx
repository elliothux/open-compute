This path installs the current formal release, starts one local instance, and deploys a minimal Worker. Formal binaries are available for macOS on Apple silicon and Linux on ARM64 or x86-64.

## Set up with an AI coding agent

Copy this prompt into Codex, Claude Code, or another coding agent. The code block has a one-click copy button:

```text
Read https://open-compute.dev/llms.txt and install the current open-compute release on this machine. Configure one local instance, inspect any existing installation first, preserve its configuration and instance data, ask before using sudo or making destructive changes, then run ocd status and report the result.
```

[`llms.txt`](https://open-compute.dev/llms.txt) contains the minimum setup and usage instructions, with links to detailed documentation when needed.

## 1. Install

Install the latest formal release:

```sh
curl -fsSL https://open-compute.dev/install.sh | sh
```

The installer selects the matching platform binary and verifies the release checksums. It installs `ocd` below `~/.local` and stores its private receipt in `~/.open-compute/install-receipt.json`; temporary downloads stay under `~/.open-compute/tmp/`. It adds `~/.local/bin` to supported shell configuration when needed, or prints one exact `export PATH=...` command. It does not create configuration, instance data, secrets, or a service.

## 2. Set up the platform

Create the recommended user configuration and data directories, register the login-scoped user service, and start the first instance:

```sh
ocd setup --yes
```

Verify the instance and open the Dashboard:

```sh
ocd status
ocd dashboard
```

`status` must report ready. `dashboard` opens a one-time login URL; it does not ask you to copy a long-lived admin token.

This creates one scoped daemon and its first isolated instance. Add more later with `ocd instance setup --name staging --yes`; then use `--instance staging` for instance-scoped commands. See [Instances](/docs/ocd/instances/).

The user service starts again at login but may stop at logout. To run a host-wide service before login, explicitly install and set up system scope:

```sh
curl -fsSL https://open-compute.dev/install.sh | sudo sh
sudo ocd setup --system --yes
```

## 3. Create a Worker project

Create an ordinary Wrangler project and keep Wrangler project-local:

```sh
mkdir hello-worker
cd hello-worker
```

```sh
mkdir src
```

Create `src/index.ts`:

```ts
export default {
  fetch(request: Request): Response {
    return Response.json({
      message: "hello from open-compute",
      path: new URL(request.url).pathname,
    });
  },
} satisfies ExportedHandler;
```

Create `wrangler.jsonc`:

```json
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "hello-worker",
  "main": "src/index.ts",
  "compatibility_date": "2026-09-08",
  "workers_dev": false
}
```

## 4. Develop and deploy

Use Wrangler directly for the fast local loop:

<Tabs syncKey="package-manager">
  <TabItem label="npm">
    <Code code="npm exec -- wrangler dev" lang="sh" />
  </TabItem>
  <TabItem label="pnpm">
    <Code code="pnpm exec wrangler dev" lang="sh" />
  </TabItem>
  <TabItem label="bun">
    <Code code="bun run wrangler dev" lang="sh" />
  </TabItem>
</Tabs>

Then deploy through the selected open-compute instance:

```sh
ocd wrangler deploy
```

Use the canonical `.localhost` origin printed by Wrangler to call the Worker. To inspect live logs:

```sh
ocd wrangler tail
```
