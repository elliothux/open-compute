# P0.6：D1 详细设计

> 状态：Implemented and verified（2026-08-25）
>
> 前置依赖：P0.1 至 P0.5；其中 P0.5.0 的 loaded-isolate facade framework 是 hard prerequisite。
>
> 平台基线：[P0.2：Workers Runtime](./p0-2-workers-runtime.md)、
> [P0.3：Resource 与 Binding Framework](./p0-3-resource-binding-framework.md)、
> [P0.4：KV](./p0-4-kv.md)、[P0.5：R2](./p0-5-r2.md)
>
> 兼容目标：还原 Cloudflare D1 Workers binding 最常用的 JavaScript API 和 SQLite 语义；不实现
> read replica、bookmark、Time Travel、完整 REST/Wrangler 管理面或 Cloudflare 计费统计。

P0.6 使用“一 D1 database 一 SQLite 文件”。`control.sqlite` 只管理 database resource、路径、
quota、backup 和 lifecycle；tenant table/index/view/trigger 与数据全部存在自己的 SQLite 文件中。

D1 的第一难点不是 SQLite，而是 binding 形状。官方 `env.DB.prepare(sql)` 和 `.bind(...)` 同步返回
可复用本地对象，只有 `all()`、`run()`、`first()`、`raw()`、`batch()` 和 `exec()` 才异步。如果把
整个 D1 binding 做成远端 `WorkerEntrypoint`，常见的 statement reuse、`batch([stmt.bind(...)])`
和同步 type error 都会漂移。

本方案沿用 P0.5.0：raw binding-scoped transport 通过 WorkerLoader env 进入 loaded Worker，项目自有
D1 facade module 在 tenant isolate 内创建 `D1Database`、`D1PreparedStatement` 和 session 对象。
statement 只是本地 immutable `{sql, params, owner}`；terminal operation 才把 flat DTO 发给 Rust
backend。

## 1. 交付形态

```text
Control API
    └── D1DatabaseController
            ├── resources(kind=d1_database)
            └── d1_databases / d1_backups / control.sqlite
                    └── D1ResourceDriver
                            └── data/d1/<account>/<resource>/data.sqlite

loaded tenant Worker isolate
    └── local D1Database facade
            ├── synchronous prepare()/bind()/withSession()
            └── terminal operation
                    └── ctx.exports.D1Transport({ props })
                            └── private BindingBackend
                                    ├── binding authorization + ResourcePin
                                    └── D1Engine
                                            ├── per-database serialized operation lane
                                            ├── SQLite authorizer/limits/progress handler
                                            └── one tenant database file
```

完成后，用户可以：

- 创建、list、rename、删除多个 D1 database；
- 把多个 database 独立绑定到同一 Worker；
- 使用 `prepare`、`bind`、`run`/`all`、`first`、`raw`、`batch` 和 `exec`；
- 创建自己的 table、index、view、trigger，并使用常用 SQLite/JSON/FTS5 能力；
- 通过 control API 应用 ordered migrations；
- 在线备份一个 database 到 system S3 prefix，并从 backup 创建新 database；
- 在 WAL recovery、长查询中断、batch rollback、response loss 和单文件损坏时得到确定行为。

### 1.1 完成定义

- 一个 D1 resource 的 tenant SQL 永远只连接自己的 SQLite 文件；
- tenant SQL 与 `control.sqlite`/其他 D1/KV/DO 文件之间没有 attach 或 shared connection 路径；
- `prepare()`/`bind()` 在 tenant isolate 同步返回普通本地 facade object，不产生 backend call；
- statement 可以复用，`batch()` 只接受同一个 database/session 创建的 statement；
- `batch()` 是单 SQLite transaction，任一失败回滚整批；
- `exec()` 使用 SQLite parser 的 tail pointer 拆语句，不用正则或简单分号切割；
- authorizer、SQLite runtime limits、progress handler、wall deadline 和 result budget 同时生效；
- database operation 在 async runtime blocking pool 执行，不阻塞 Tokio core thread；
- 同一 database 一次只执行一个 operation，不同 database 可以并行；
- SQLite commit 后 response loss 返回 result-unknown，不自动重放 mutation；
- 真实 stock workerd Gate 连续三轮 fresh process 通过，P0.2 至 P0.5 无回归。

### 1.2 非目标

- D1 read replication、region/colo routing、Sessions bookmark 或 Time Travel；
- Cloudflare 10 GB paid quota 的默认承诺；本地默认 quota 更保守但可配置；
- Cloudflare 精确 `rows_read` billing 计数；本方案返回明确标记的 local estimate；
- 完整 D1 REST API、Wrangler remote protocol、import/export API 或 dashboard；
- alpha-only `dump()`；backup/restore 走平台 control API；
- 跨 database query、`ATTACH`、`DETACH` 或 federated SQL；
- tenant-controlled SQLite extension、任意 virtual table module 或 host function；
- 在一个 Worker request 内跨多次 D1 call 保持显式 SQL transaction；
- in-place restore、PITR 或复制正在运行的数据库文件；
- 多节点同时打开同一个 SQLite 文件；
- 把 D1 database 放在 S3、NFS 或 SMB share 上直接运行。

## 2. Binding 架构决策

### 2.1 不直接使用纯 JSRPC statement object

以下 Cloudflare 常见代码必须原样工作：

```js
const stmt = env.DB.prepare("SELECT * FROM users WHERE id = ?");
const one = await stmt.bind(1).first();
const many = await env.DB.batch([
  stmt.bind(1),
  stmt.bind(2),
]);
```

`stmt` 必须立即存在、可复用，并能被 `batch()` 本地检查 owner。若 `prepare()` 返回 RpcPromise/RpcTarget：

- type error 和 arity error 会延迟；
- statement array 变成跨 isolate capability array；
- owner identity、reuse 和 disposal 语义依赖 JSRPC implementation detail；
- 很难保证与普通 D1 object 相同的 property/method 行为。

因此 raw transport 只暴露一个 flat terminal call，例如
`query(mode, statements, requestMeta)`；tenant isolate 的 facade 自己序列化 statement。

### 2.2 为什么当前不选 workerd `WrappedBinding`

upstream workerd 的 D1 API 使用 internal module + native `WrappedBinding`，它确实解决了“本地 facade
包装 Fetcher”的问题。但 stock workerd 当前通过静态 config 初始化 wrapper，并在 C++
`instantiateWrapper()` 中设置 serialization 所需的 wrapper module。普通 JavaScript 构造出来的
`WrappedBinding` 没有这个内部 module 标记，不能安全作为动态 WorkerLoader env 值序列化。

本平台还要求每个 deployment binding 都携带不同的 P0.3 scoped props。为每个 database 重生成
workerd static config 或重启 workerd 违背动态 loader 架构，fork workerd 也不在范围内。

所以 P0.6 选择 WDL 的 stock-workerd 路径：注入 local client facade + generated wrapper。若未来
upstream 暴露支持动态 scoped Fetcher 的 public wrapped-binding factory，可以在新 capability version
中重新评估，不能在 P0.6 同时维护两条路径。

### 2.3 P0.6.0 Hard Gate

P0.5.0 已证明通用 wrapper/injection。P0.6.0 再用 fake D1 transport 验证 D1 特有语义：

| Gate | 断言 |
| --- | --- |
| DF-01 | `prepare()` 同步返回，且 fake transport 调用数仍为 0 |
| DF-02 | `bind()` 同步返回新 statement，原 statement 可复用 |
| DF-03 | run/all/first/raw 只在 terminal call 时发送一个 flat DTO |
| DF-04 | batch 接受同 DB reused statements，并保持顺序 |
| DF-05 | batch 拒绝其他 DB、其他 session 和伪造普通 object |
| DF-06 | bind type conversion/type error 在 tenant isolate 同步发生 |
| DF-07 | BLOB 参数跨 JSRPC 不经 JSON/base64 全量膨胀 |
| DF-08 | magic column `__proto__` 不改变 result object prototype |
| DF-09 | object/default class/named entrypoint 和 importable env 都得到 local facade |
| DF-10 | raw transport、binding props 和内部 module 不可从 tenant env 取得 |
| DF-11 | facade/source version 进入 descriptor hash，cold/warm/restart 不漂移 |
| DF-12 | P0.5 R2 facade 与 D1 facade 同时存在时 wrapper 只生成一层且幂等 |

任一 Gate 失败都先修 injection/facade framework，不能开始 D1 SQLite engine。

## 3. Cloudflare 常用 API 兼容面

以当前官方 [D1 Database API](https://developers.cloudflare.com/d1/worker-api/d1-database/)、
[prepared statement methods](https://developers.cloudflare.com/d1/worker-api/prepared-statements/)、
[type conversion](https://developers.cloudflare.com/d1/worker-api/) 和
[D1 limits](https://developers.cloudflare.com/d1/platform/limits/) 为基线。

### 3.1 Worker binding surface

```ts
interface D1Database {
  prepare(query: string): D1PreparedStatement
  batch<T = Record<string, unknown>>(
    statements: D1PreparedStatement[]
  ): Promise<D1Result<T>[]>
  exec(query: string): Promise<{ count: number; duration: number }>
  withSession(
    constraint?: "first-primary" | "first-unconstrained"
  ): D1DatabaseSession
}

interface D1PreparedStatement {
  bind(...values: unknown[]): D1PreparedStatement
  run<T = Record<string, unknown>>(): Promise<D1Result<T>>
  all<T = Record<string, unknown>>(): Promise<D1Result<T>>
  first<T = Record<string, unknown>>(columnName?: string): Promise<T | unknown | null>
  raw<T = unknown>(options?: { columnNames?: boolean }): Promise<T[][]>
}
```

`run()` 与 `all()` 作为 alias 返回同一 D1Result shape。`first()` 和 `raw()` 不返回 meta。

### 3.2 兼容矩阵

| 能力 | P0.6 | 说明 |
| --- | --- | --- |
| synchronous `prepare` | 支持 | 本地 immutable statement |
| synchronous `bind` | 支持 | 返回新 statement |
| `run` / `all` | 支持 | 等价，始终有 results array |
| `first()` / `first(column)` | 支持 | missing row 为 null，missing column 抛错 |
| `raw()` / column names | 支持 | 保留 column order 和 duplicate name |
| `batch()` | 支持 | 同 DB transaction，全回滚 |
| `exec()` | 支持 | 多 statement，前缀可已提交 |
| positional parameters | 支持 | `?`、`?NNN` 和 SQLite named slot 的位置绑定 |
| JS/D1 type conversion | 支持 | null/number/string/bool/BufferSource |
| local session | 部分支持 | 两个 constraint；单 primary，bookmark 不支持 |
| migrations | 平台扩展 | control API，DB 内原子 migration ledger |
| backup/restore | 平台扩展 | restore 创建新 resource |
| `dump()` | 不支持 | alpha-only API，不进入 P0 |
| arbitrary bookmark | 不支持 | 返回 `D1_SESSION_UNSUPPORTED` |
| read replica | 不支持 | 所有 query 在本地 primary file |
| experimental `query()` | 不支持 | 不属于 P0 常用面 |

### 3.3 Type conversion

写入：

| JavaScript | SQLite | 规则 |
| --- | --- | --- |
| `null` | NULL | 原样 |
| safe integer Number | INTEGER | i64 范围内 |
| finite non-integer Number | REAL | NaN/Infinity 拒绝 |
| String | TEXT | UTF-8 |
| Boolean | INTEGER | false=0，true=1 |
| ArrayBuffer/View | BLOB | 只传 view 范围 |
| `undefined` | 不支持 | `D1_TYPE_ERROR` |
| BigInt/object/Date/function/symbol | 不支持 | `D1_TYPE_ERROR` |

读取：NULL -> null、INTEGER/REAL -> Number、TEXT -> String、BLOB -> `number[]`。SQLite 内部 i64
超出 JavaScript safe integer 时转换为 Number 可能失去精度，这与 D1 当前公开限制一致；不得偷偷
改成 BigInt 或 string。

ArrayBuffer/View 在 loaded isolate 到 loader host 使用 structured binary value，loader host 到 Rust
使用 bounded binary frame；禁止 JSON number array/base64 作为内部 transport。只有最终返回给 tenant
的 BLOB row value按 D1 shape 转为 `number[]`。

### 3.4 D1Result

```ts
type D1Result<T> = {
  success: true
  results: T[]
  meta: {
    served_by: "open-compute-local"
    served_by_primary: true
    duration: number
    changes: number
    last_row_id: number
    changed_db: boolean
    size_after: number
    rows_read: number
    rows_written: number
  }
}
```

`served_by_region` 和 `served_by_colo` 不伪造。`rows_written` 使用 SQLite changes；`rows_read` 在
P0.6 只能返回 output/materialized row count 的 local estimate，不代表 SQLite 实际扫描行数，也不
用于 billing。metrics 和文档必须标记 estimate，不能声称与 Cloudflare 计费一致。

## 5. Control plane schema

新增 `006_d1.sql`。

### 5.1 `d1_databases`

```sql
CREATE TABLE d1_databases (
  resource_id          TEXT PRIMARY KEY REFERENCES resources(id),
  storage_key          TEXT NOT NULL UNIQUE,
  schema_version       INTEGER NOT NULL CHECK(schema_version >= 1),
  quota_bytes          INTEGER NOT NULL CHECK(quota_bytes >= 67108864),
  created_at_ms        INTEGER NOT NULL,
  last_opened_at_ms    INTEGER,
  last_quick_check_ms  INTEGER,
  last_backup_at_ms    INTEGER,
  restore_backup_id    TEXT REFERENCES d1_backups(id)
) STRICT;
```

identity fields 与 P0.4 一样 immutable。insert guard 要求 matching `resources(kind=d1_database,
state=creating)`；live locator 不能直接删除；tombstone 后 retire locator。

### 5.2 `d1_backups`

```sql
CREATE TABLE d1_backups (
  id                    TEXT PRIMARY KEY,
  source_resource_id    TEXT NOT NULL REFERENCES resources(id),
  state                 TEXT NOT NULL CHECK(state IN (
                          'creating', 'ready', 'failed', 'deleting', 'tombstoned'
                        )),
  object_key            TEXT,
  sha256                BLOB,
  size_bytes            INTEGER,
  d1_schema_version     INTEGER NOT NULL,
  sqlite_user_version   INTEGER NOT NULL,
  created_at_ms         INTEGER NOT NULL,
  completed_at_ms       INTEGER,
  error_code            TEXT,
  idempotency_key       TEXT NOT NULL,
  request_fingerprint   BLOB NOT NULL,
  UNIQUE(source_resource_id, idempotency_key)
) STRICT;
```

字段/trigger 与 P0.4 backup contract 对齐：ready 才能拥有完整 object/hash/size；identity 和 request
fingerprint immutable；S3 key 位于 `system/backups/d1/`，tenant R2 永远不可达。

Migration ledger 不放 `control.sqlite`。应用 migration SQL 和写 ledger 必须在同一个 tenant DB
transaction 中完成，跨两个 SQLite 文件无法原子提交。

## 6. 物理目录与 lifecycle

### 6.1 Layout

```text
data/d1/
├── .staging/<resource-id>.<operation-id>/data.sqlite
├── .trash/<resource-id>.<operation-id>/data.sqlite
└── <account-id>/<resource-id>/data.sqlite
```

canonical storage key：

```text
v1/<account-id>/<resource-id>/data.sqlite
```

实现新增 `D1Paths`，复用 `storage::fs` 的 absolute root、containment、owner、mode、no-symlink 和
atomic rename primitive。不要让 KV 的 `KvPaths` 变成带 product string 的万能路径 builder；共享
安全 primitive，保留 product-specific locator validation。

### 6.2 Create

1. P0.3 reserve resource creating；
2. 插入 immutable `d1_databases` locator/quota；
3. 在 `.staging` 创建 database；
4. 设置 create-time pragmas，创建 internal schema/identity；
5. 关闭连接并执行 `quick_check`/identity/schema validation；
6. fsync file + staging dir；
7. same-filesystem atomic rename 到 live dir并 fsync parent；
8. resource ready。

`reconcile()` 处理 staging/live/absent 的 crash matrix。live identity 与 resource/account 不匹配时
标记 `D1_IDENTITY_MISMATCH`，不能覆盖或另建文件。

### 6.3 Delete

1. P0.3 referrer check、deleting fence、drain `ResourcePin`；
2. handle manager 拒绝新 acquire，等待 current operation lane 退出；
3. checkpoint/关闭 connection；
4. atomic rename live dir 到 `.trash`；
5. fsync parent；
6. 逐个验证并删除 `data.sqlite`、`-wal`、`-shm`；
7. fsync trash dir，确认 live identity absent；
8. tombstone resource。

restart 根据 resource state 和 canonical staging/trash name 幂等收敛。同名重建使用新 UUID 和新目录。

## 7. Tenant database internal schema

每个新 database 只预建两个 reserved table；tenant schema 仍为空。

```sql
CREATE TABLE __open_compute_meta (
  key   TEXT PRIMARY KEY,
  value BLOB NOT NULL
) STRICT, WITHOUT ROWID;

CREATE TABLE __open_compute_migrations (
  id            INTEGER PRIMARY KEY,
  name          TEXT NOT NULL UNIQUE,
  sha256        BLOB NOT NULL CHECK(length(sha256) = 32),
  applied_at_ms INTEGER NOT NULL,
  UNIQUE(name, sha256)
) STRICT;
```

meta 至少保存：

```text
format = open-compute-d1
schema_version = 1
resource_id = <uuid>
account_id = <uuid>
created_at_ms = ...
```

tenant authorizer 拒绝读取、修改、drop 或 shadow `__open_compute_*`。其他以 `__` 开头的名字不预留，
避免无必要扩大兼容偏差。

## 8. Connection 与 SQLite hardening

### 8.1 Connection pragmas

每次打开连接设置并核对：

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = FULL;
PRAGMA foreign_keys = ON;
PRAGMA trusted_schema = OFF;
PRAGMA recursive_triggers = ON;
PRAGMA temp_store = MEMORY;
PRAGMA busy_timeout = 5000;
PRAGMA wal_autocheckpoint = 1000;
PRAGMA mmap_size = 0;
```

按 frozen quota 设置 `max_page_count`。连接还要启用 `SQLITE_DBCONFIG_DEFENSIVE`、关闭 extension
loading，并确认没有自定义 file-access function。

tenant 不能通过 SQL 改写这些 pragma。foreign key policy 是 database 固定 contract，不允许一次 call
关掉后影响后续 call。

### 8.2 SQLite runtime limits

使用 `sqlite3_limit()` 设置：

- `SQLITE_LIMIT_LENGTH = 2_000_000`；
- `SQLITE_LIMIT_SQL_LENGTH = 100_000`；
- `SQLITE_LIMIT_COLUMN = 100`；
- `SQLITE_LIMIT_VARIABLE_NUMBER = 100`；
- `SQLITE_LIMIT_FUNCTION_ARG = 32`；
- `SQLITE_LIMIT_LIKE_PATTERN_LENGTH = 50`；
- `SQLITE_LIMIT_ATTACHED = 0`；
- bounded compound-select、trigger-depth 和 expression-depth。

rusqlite 需要显式启用对应 `hooks`/`limits` support；不能因为 high-level API 不方便就只在 JS
facade 做 limit。

### 8.3 Authorizer

authorizer 是 compile-time/VM authorization boundary，不是 SQL string blacklist。至少拒绝：

- `ATTACH`、`DETACH`；
- tenant `BEGIN`、`COMMIT`、`ROLLBACK`、`SAVEPOINT`；
- 读取/写入/创建/drop `__open_compute_*`；
- 写 `sqlite_schema`、`PRAGMA writable_schema`；
- extension loading 和 `load_extension()`；
- `VACUUM`/`VACUUM INTO`；
- filesystem-affecting、connection-persistent 或 security pragma；
- TEMP database/table/index/view/trigger；
- 未 allowlist 的 virtual table module；P0.6 只允许 bundled FTS5；
- 非 `main` database 的 table access。

允许普通 SELECT/DML/DDL、main schema introspection，以及 ORM 常用只读 pragma：

```text
table_info, table_xinfo, index_list, index_info, index_xinfo,
foreign_key_list, foreign_key_check, database_list,
user_version(read), application_id(read)
```

`user_version`/`application_id` write 可供 migration control path 使用，tenant binding 默认拒绝。
allowlist 需要 conformance fixture 驱动扩展，不能用“所有 PRAGMA 都允许，再禁几个”的方式。

host 自己的 transaction、internal meta 和 migration ledger 操作不走 tenant SQL channel。实现使用
scoped `SqlExecutionGuard` 安装/恢复 authorizer、limits 和 progress callback，不能在同一个 connection
上留下上一次 operation 的 host mode。

### 8.4 Progress 与 cancellation

每 1000 VM opcodes 检查：

- monotonic deadline；
- operation cancellation flag；
- accumulated VM steps；
- shutdown/drain token。

超限返回 `SQLITE_INTERRUPT` 后映射稳定 D1 limit/timeout error。另保留 `InterruptHandle` 供
operation timeout 和 shutdown 从执行线程外中断。client disconnect 只能作为额外 signal，不能作为
唯一 cancellation contract。

## 9. D1 facade 与 transport

### 9.1 Local object model

facade 用 WeakMap/private state，不把 raw stub、SQL params 或 owner 作为 enumerable public fields：

```text
D1DatabaseState     = rawStub + requestContext
D1SessionState      = rootDatabase + constraint
D1StatementState    = databaseOrSession + sql + normalizedParams + owner
```

`prepare(sql)`：

- 要求 non-empty string；
- 检查 100,000-byte JS-side fast limit；
- 不访问 backend、不真正 compile；
- 返回新的 local statement。

`bind(...values)`：

- 同步 normalize type；
- 返回新 statement，不修改原 statement；
- backend compile 后再次校验 parameter count/type/bytes。

### 9.2 Flat terminal protocol

raw `D1Transport extends WorkerEntrypoint` 只需要：

```ts
query(
  mode: "all" | "run" | "raw" | "batch",
  statements: Array<{ sql: string; params: unknown[] }>,
  requestMeta: { requestId?: string }
): Promise<TransportResult>

exec(sql: string, requestMeta: { requestId?: string }): Promise<D1ExecResult>
```

transport props 沿用 P0.3 binding ID/deployment/hash/generation/permission。read-only binding 在 backend
compile statement 后使用 `sqlite3_stmt_readonly()` 再次判断；不能信任 caller 提交的 mode。

loader host 到 Rust 使用独立 authenticated D1 frame/content type。SQL、params 和 result 都有外层
frame budget；BLOB 是 length-delimited bytes，不进 JSON。

### 9.3 Result object safety

object rows按 column order 构造。duplicate column name 使用后出现的值覆盖前值，与普通 JS object
形状一致；`raw()` 保留全部 duplicate columns。`__proto__`、`constructor` 等 magic name 使用
`Object.defineProperty` 写 data field，不能改变 result prototype。

facade 不信任 transport shape：column count、row width、meta field、BLOB bytes 和 total result size
都要再次校验，protocol mismatch 返回稳定 internal error。

## 10. Statement execution

### 10.1 Prepare/compile

terminal call 在 blocking execution thread：

1. acquire resource pin 和 per-DB operation lane；
2. 安装 `SqlExecutionGuard`；
3. `sqlite3_prepare_v3` compile；
4. 验证 tail 只有 whitespace/comment；prepared statement API 一次只允许一条 SQL；
5. 检查 parameter count、column count、readonly 和 authorizer result；
6. bind normalized values；
7. step/materialize，在 row/byte/time/VM budget 内完成；
8. finalize statement并恢复 guard。

不能按 SQL 前缀猜 read/write。CTE、pragma、returning、trigger 和 user-defined view 都要求以 SQLite
prepared statement/authorizer 结果为准。

### 10.2 `all()` 与 `run()`

两者执行同一路径并返回 D1Result。DML `RETURNING` 可以产生 results；普通 INSERT/UPDATE/DELETE
results 为空。`changes` 使用本 statement 的 `sqlite3_changes64()`，`last_row_id` 使用执行后的
`sqlite3_last_insert_rowid()`。

### 10.3 `first()`

facade 调用 all/raw transport mode，但只保留第一行。SQL 本身不会自动加 `LIMIT 1`，与官方行为一致。
指定 column 不存在时抛 `D1_COLUMN_NOTFOUND`；存在但值为 undefined 的情况不会出现，因为 SQLite
没有 undefined。

### 10.4 `raw()`

backend 返回 `{columns, rows}`。facade 默认只返回 rows；`{columnNames:true}` 在第 0 行插入 column
name copy。任何其他 option key 返回 type error。

### 10.5 Meta

- `duration`：SQLite compile/step/materialize 的 wall milliseconds，不含 JSRPC/network；
- `changes`/`rows_written`：statement changes；
- `last_row_id`：SQLite last insert rowid，转换为 Number；
- `changed_db`：`sqlite3_stmt_readonly() == false` 且 statement 成功；
- `size_after`：logical `page_count * page_size`，不把 WAL file bytes冒充 database size；
- `rows_read`：P0.6 local estimate，等于 materialized output rows；
- `served_by`：固定 `open-compute-local`。

## 11. Batch 与 exec

### 11.1 `batch()`

facade 先验证：

- input 是 non-empty array；
- 1 至 100 statements；
- 每个值都来自同一个 database/session 的 local WeakMap state；
- SQL/params aggregate frame 不超限。

backend 先 compile 全部 statements，再决定 transaction mode：全 readonly 使用 deferred read
transaction；任一可能写入使用 `BEGIN IMMEDIATE`。随后按数组顺序执行并收集结果。任一 compile、
bind、authorizer、limit 或 step error 都 rollback 整批，不返回 partial success array。

transaction commit 成功后才返回 results。commit 后 response loss 是 `D1_RESULT_UNKNOWN`：整批可能
已经提交，不能自动重试。

### 11.2 `exec()`

`exec(sql)` 接受一个 non-empty string。Rust backend 使用 SQLite prepare API 的 tail pointer 循环
解析 1 至 100 条 statement，正确处理 string/comment/trigger body；禁止 JS regex 或按行/分号简单切割。

exec 不创建整批 transaction：每条 statement 按 SQLite autocommit 顺序执行，错误时停止，之前已
commit 的 statement 保留。返回 `{count, duration}`；错误包含 stable statement index，但不回显完整
SQL 或 bound data。

显式 transaction/savepoint statement 由 authorizer 拒绝，避免 transaction 跨 binding call 或在
exec 中制造不清晰的 partial ownership。需要原子多语句时使用 `batch()` 或 migration API。

## 12. Migrations

### 12.1 Control contract

最小 API：

```text
GET  /v1/accounts/:account/d1/databases/:resource/migrations
POST /v1/accounts/:account/d1/databases/:resource/migrations/apply
```

apply request：

```json
{
  "migrations": [
    { "id": 1, "name": "0001_init.sql", "sha256": "...", "sql": "..." }
  ]
}
```

### 12.2 Apply algorithm

每个 migration 独立 transaction：

1. acquire same per-DB operation lane；
2. 查询 `__open_compute_migrations`；
3. 相同 id/name/hash 已存在则幂等跳过；任一 identity 同名异 hash 返回 drift error；
4. 使用 SQLite tail parser 拆 migration SQL；
5. 在 migration-specific but bounded deadline/statement count 下执行；
6. 同一 transaction 写 ledger row；
7. commit 后才开始下一 migration。

migration SQL 仍受 ATTACH/extension/filesystem/internal-table authorizer；只额外允许 host 管理
`user_version` 和 internal ledger。SQL text 不存 control DB、日志或 S3 manifest，只存 hash/name/time。

不在 deploy、cold load 或 request path 自动跑 migration。CLI/deployer 必须先显式 apply，再发布依赖
新 schema 的 Worker，失败时 active deployment 不变。

## 13. Operation lane 与 handle manager

### 13.1 一 database 串行

P0.6 对每个 database 只开放一个 foreground operation lane。原因：

- Cloudflare D1 单 database 本身也是顺序执行模型；
- arbitrary SQL 的 transaction、DDL、trigger 和 connection state 比 KV 固定 SQL 更复杂；
- 串行可以消除绝大多数 `SQLITE_BUSY` 和 connection-state leakage；
- SMB workload 更需要确定恢复语义，而不是提前做 read pool。

不同 database 使用不同 lane 并行。超过 per-DB queued operation 上限返回 `D1_OVERLOADED`，不能无界
排队占内存。

### 13.2 Handle lifecycle

handle 包含 canonical path、connection、operation queue、availability 和 last-used。global LRU 只驱逐
idle、无 pin、无 queued operation、无 backup 的 handle。驱逐前 passive checkpoint；delete/backup
使用显式 exclusive lifecycle state。

可以复用 P0.4 handle manager 的 admission/LRU/pin 思路，但不共用 `KvEngine` 或假设 D1 也有 reader
pool。先做独立 `D1HandleManager`，等两个实现稳定后再提取真正相同的 primitive。

### 13.3 WAL 与 disk pressure

- foreground mutation 成功后按 page/WAL thresholds 调度 passive checkpoint；
- WAL hard threshold 触发更积极 checkpoint，并在无法回收时拒绝新 mutation；
- database quota 同时计算 main + WAL growth 风险，不能只在 commit 后发现越界；
- platform disk hard watermark 拒绝 DDL/DML/migration/restore，read 继续；
- `SQLITE_FULL` 映射 quota/disk error，不当作 corruption。

## 14. Backup 与 restore

### 14.1 Online backup

流程复用 P0.4 durable backup orchestration，但 source 是 D1：

1. reserve `d1_backups(state=creating)`；
2. acquire resource pin 和 backup lease；
3. 使用 SQLite Online Backup API 生成一致 snapshot 到 secure `backup-staging/`；
4. 对 snapshot 做 identity/schema/quick_check；
5. 计算 SHA-256/size；
6. 上传 immutable `system/backups/d1/<resource>/<backup>/data.sqlite`；
7. 上传 manifest；
8. HEAD/GET verify；
9. 标记 ready，删除 local staging。

Online Backup 读取一个一致 snapshot，普通 query 可以继续；同一 database 同时只允许一个 backup，
且全局 backup concurrency 有上限。

### 14.2 Restore creates new identity

restore 只能创建新 resource：

1. 下载并验证 manifest/hash/size/schema；
2. 写入新 resource 的 `.staging`；
3. quick_check；
4. 在 trusted transaction 更新 `__open_compute_meta` 中的 account/resource/created identity；
5. 保留 tenant schema/data 和 migration ledger；
6. 再次验证 authorizer/integrity；
7. atomic publish；
8. resource ready。

不覆盖原 database，不复用原 resource ID，也不自动切换 deployment binding。用户必须部署新 version
显式绑定 restored resource。

### 14.3 Backup 不是 D1 Time Travel

P0.6 没有 continuous WAL archive、bookmark 或 arbitrary point restore。backup 是显式、离散 snapshot；
retention 由 operator policy 管理。全局 platform backup 仍遵循总方案的 maintenance window，不声称
R2/system objects 与所有 SQLite 同一时刻原子。

## 15. Corruption 与 health isolation

首次打开/定期执行：

- canonical path/owner/mode/symlink validation；
- `__open_compute_meta` identity/schema；
- `PRAGMA quick_check(1)`；
- pragma/hardening/authorizer self-test；
- WAL open/recovery。

运行中遇到 `SQLITE_CORRUPT`、`NOTADB`、identity mismatch 或 impossible schema：

1. 当前 operation 返回 stable corruption error；
2. handle 进入 quarantined/unavailable，不再重开风暴；
3. 持久化 resource availability code；
4. 其他 D1/KV/control database 继续服务；
5. operator 可从 known-good backup 创建新 resource。

不能自动删除 WAL、运行 `.recover`、覆盖文件或原地 restore。`integrity_check` 全库扫描只在 doctor/
operator action 运行，不放 request path。

## 16. Failure 与 result-unknown

| Operation | Failure semantics |
| --- | --- |
| readonly query 在 step 前失败 | 无 mutation，可由 caller 判断重试 |
| single DML/DDL 明确 rollback | 无 commit，返回 deterministic error |
| single DML commit 后 response loss | `D1_RESULT_UNKNOWN`，可能已提交 |
| batch 任一 statement 失败 | 整批 rollback |
| batch commit 后 response loss | `D1_RESULT_UNKNOWN`，整批可能已提交 |
| exec 第 N 条失败 | N 之后不执行，之前 autocommit 保留 |
| exec response loss | 已执行条数和 commit 前缀未知 |
| timeout/progress interrupt | 当前 statement rollback；此前 exec prefix 仍保留 |
| process crash | SQLite WAL recovery；未 commit transaction 不生效 |

backend 不自动 retry tenant SQL，即使 error 看起来是 busy/timeout。retry write 会重复外部副作用、
自增 ID 或 migration。只有 control-plane idempotent create/backup/migration reservation 可以按其独立
protocol 重放。

## 17. Session policy

单节点只有一个 primary，普通 D1 call 已提供 read-your-writes。P0.6 仍提供最小 local session object，
方便使用当前 API 的应用运行：

- `withSession()`、`first-primary`、`first-unconstrained` 都返回同一 primary policy；
- session 支持 `prepare()`、`batch()`；
- `getBookmark()` 始终返回 `null`；
- 传任意 bookmark string 返回 `D1_SESSION_UNSUPPORTED`，不假装已满足 bookmark；
- session 不跨 database，也不创建长事务。

这是 API shape compatibility，不是 replica/bookmark implementation。

## 18. Control API

```text
POST   /v1/accounts/:account/d1/databases
GET    /v1/accounts/:account/d1/databases

PATCH  /v1/accounts/:account/d1/databases/:resource
```

测试需要 query 时通过受控 fixture Worker 或后续 CLI contract。

## 19. Error mapping

| Code | Retryable | 说明 |
| --- | --- | --- |
| `D1_TYPE_ERROR` | 否 | bind value 不支持 |
| `D1_SQL_INVALID` | 否 | empty/multiple/parse error |
| `D1_PARAMETER_MISMATCH` | 否 | bind count 不匹配 |
| `D1_AUTHORIZER_DENIED` | 否 | ATTACH/pragma/internal schema 等被拒绝 |
| `D1_LIMIT_ERROR` | 否 | SQL/param/row/result/VM limit |
| `D1_TIMEOUT` | 可由 caller 判断 | query/batch deadline |
| `D1_COLUMN_NOTFOUND` | 否 | first(column) 不存在 |
| `D1_INVALID_BATCH` | 否 | 非 statement/cross DB/too many |
| `D1_SESSION_UNSUPPORTED` | 否 | bookmark/replica session |
| `D1_MIGRATION_DRIFT` | 否 | 同 id/name 不同 hash |
| `D1_DATABASE_FULL` | 否 | frozen quota 或 disk hard limit |
| `D1_OVERLOADED` | 是 | per-DB queue/global blocking pool 饱和 |
| `D1_RESULT_UNKNOWN` | 需幂等判断 | commit 后 response loss |
| `D1_DATABASE_CORRUPT` | 否 | resource-local corruption |
| `D1_IDENTITY_MISMATCH` | 否 | file/resource identity 不一致 |
| `D1_INTERNAL_PROTOCOL_ERROR` | 否 | facade/transport/backend shape mismatch |

SQLite raw message 需要去掉 path、SQL payload 和 bound value；可以保留安全的 syntax/category 和
statement index。tenant error 不包含 storage key、filesystem path、connection debug、internal table
内容或其他 resource ID。
