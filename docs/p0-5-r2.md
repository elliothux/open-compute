# P0.5：R2 详细设计

> 状态：Implemented and verified（2026-08-25）
>
> 前置依赖：P0.1 至 P0.4 已按当前 checkout 和用户确认跑通。
>
> 直接依赖：[P0.1：Platform Foundation](./p0-1-platform-foundation.md)、
> [P0.2：Workers Runtime](./p0-2-workers-runtime.md)、
> [P0.3：Resource 与 Binding Framework](./p0-3-resource-binding-framework.md)
>
> 兼容目标：还原 Cloudflare R2 Workers binding 的常用 API；对象字节只依赖已配置的
> S3-compatible provider，不在 SQLite 镜像 object catalog。

P0.5 把 P0.1 已验证的 S3 client 扩展为 tenant-facing virtual R2 bucket。一个逻辑 bucket
对应外部 S3 bucket 下的一个不可伪造前缀；`control.sqlite` 只保存 resource lifecycle 和物理
前缀，object bytes、metadata 与 listing 以 S3 为 authority。

本阶段同时补上一层后续 D1 也需要的 loaded-isolate facade。P0.4 的 KV 方法和返回值都可以直接
跨 JSRPC；R2 不行：`R2Object.writeHttpMetadata()` 是同步方法，`R2ObjectBody` 还需要本地
`body`、`bodyUsed`、`arrayBuffer()`、`text()`、`json()` 和 `blob()`。因此不能让 tenant 直接
使用远端 `WorkerEntrypoint` stub，也不能把这些方法降级成异步 RPC。

## 1. 交付形态

```text
Control API
    └── R2BucketController
            ├── resources(kind=r2_bucket)
            └── r2_buckets / control.sqlite
                    └── R2ResourceDriver
                            └── tenant/r2/v1/<resource-id>/...

loaded tenant Worker isolate
    └── local R2Bucket facade
            ├── local R2Object / R2ObjectBody
            └── terminal call only
                    └── ctx.exports.R2Transport({ props })
                            └── private BindingBackend
                                    ├── binding authorization + ResourcePin
                                    └── R2ObjectStore
                                            └── external S3-compatible provider
```

完成后，用户可以：

- 创建、list、rename 和删除多个 logical R2 bucket；
- 在不同 deployment 中按 immutable resource ID 绑定 bucket；
- 使用 `head`、`get`、`put`、`delete` 和 `list`；
- 流式读取和写入 object，而不把完整 object 放进 JS 或 Rust heap；
- 使用 single range、ETag/date read condition、ETag write condition、HTTP metadata 和 custom
  metadata；
- 获得本地 `R2Object`/`R2ObjectBody` facade 和常用 body helper；
- 在 restart、S3 timeout/5xx、同名重建和 bucket 删除恢复时保持确定行为。

### 1.1 完成定义

- tenant 不能获得 S3 endpoint、credential、physical bucket 或 physical prefix；
- `system/` artifact prefix 与 `tenant/r2/` prefix 在配置、类型和运行时三层隔离；
- 一个 logical bucket 的 object 不能通过 key、cursor 或 binding tamper 越界到另一个 bucket；
- 不对 user key 做路径 normalization、percent decode 或 Unicode normalization；
- object bytes 和 metadata 以 S3 为 authority，SQLite 中不存在 object catalog；
- `put` 先落 secure local staging，再做一次 replayable single-part S3 PUT；
- successful mutation 返回后，后续 `head/get/list` 必须能观察到新状态；
- conditional PUT 必须由 provider 原子执行，不能用 `HEAD + PUT` 伪造；
- list cursor 不暴露 provider token，并绑定 bucket generation 和查询参数；
- loaded-isolate facade Gate 覆盖所有 P0.2 支持的 entrypoint 形态；
- 真实 stock workerd Gate 连续三轮 fresh process 通过，P0.2 至 P0.4 无回归。

### 1.2 非目标

- S3-compatible public API、presigned URL 或 tenant S3 credential；
- `createMultipartUpload()`、`resumeMultipartUpload()` 和 multipart lifecycle；
- SSE-C、bucket encryption policy、bucket lock、lifecycle rule 或 custom domain；
- `InfrequentAccess` storage class；P0.5 只返回和接受 `Standard`；
- Cloudflare 的约 4.995 TiB object 上限；P0.5 是 bounded single-part implementation；
- Cloudflare 全量 checksum selection；P0.5 计算 MD5，并可验证一个调用方提供的 MD5；
- 跨 provider replication、provider failover 或平台级 object backup；
- 在 SQLite 维护 object size、ETag、quota 或 list secondary index；
- 删除 non-empty bucket 时默认递归清空；强制清空必须显式请求。

## 2. P0.5.0：loaded-isolate facade Gate

### 2.1 为什么 P0.4 方案不能直接复制

P0.4 的 `env.KV.get()` 本身返回 Promise，最终值是 string、Map、ArrayBuffer、ReadableStream
或普通 record，适合 custom JSRPC binding。

R2 的返回对象带本地行为：

```js
const object = await env.BUCKET.get("avatar.png");
const headers = new Headers();
object.writeHttpMetadata(headers);       // 同步修改同一个 Headers
return new Response(object.body, { headers });
```

如果 `object` 是远端 RPC target：

- `writeHttpMetadata()` 会变成异步调用，且不能同步修改调用方的 `Headers`；
- `object.body` 会成为远端 property/promise，而不是本地 `ReadableStream`；
- `bodyUsed` 和一次消费语义不能由 tenant isolate 正确维护。

所以 P0.5 采用 WDL 已验证的结构：把 raw binding-scoped transport 放进 `WorkerCode.env`，同时给
loaded Worker 注入项目自有 facade module 和 deterministic main-module wrapper。wrapper 在 tenant
isolate 内把 raw stub 替换为本地 `R2Bucket` 对象，只有 terminal operation 穿过 JSRPC。

### 2.2 注入后的调用路径

```text
WorkerCode.env.BUCKET = raw R2Transport stub
WorkerCode.modules += reserved R2 facade modules + generated wrapper
WorkerCode.mainModule = generated wrapper

generated wrapper
    ├── import tenant original main module
    ├── wrap env.BUCKET -> new local R2Bucket(rawStub)
    ├── call tenant handler / WorkerEntrypoint constructor with wrapped env
    └── re-export wrapped named entrypoints
```

`R2Bucket.get()` 调用 raw stub 后收到 `{ meta, body: ReadableStream }`，再在 tenant isolate 创建
`R2ObjectBody(meta, body)`。`head()` 和 `list()` 同理在本地创建 `R2Object`。

### 2.3 注入不变量

- 注入 module name 使用平台保留前缀，deploy 时拒绝 tenant bundle 中的同名 module；
- wrapper source、facade source 和 facade capability version 进入实际 WorkerCode descriptor hash；
- retained deployment 的注入版本不可漂移；升级 facade 必须产生新 deployment 或新 capability；
- wrapper 必须覆盖 object handler、function handler、default `WorkerEntrypoint` 和声明支持的 named
  `WorkerEntrypoint`；
- 使用 `cloudflare:workers` 的 scoped env 能力时，importable env 也只能看到 wrapped env；
- raw stub、内部 binding 名和平台保留 env 不得出现在 tenant 可枚举 env；
- facade module 本身不含 token、credential、path 或 resource ID；即使被 tenant import，也不能凭空
  构造 capability；
- validation WorkerCode 与 runtime WorkerCode 使用同一 injection planner，不能只验证原始 main。

### 2.4 P0.5.0 Hard Gate

在写 S3 product logic 前，用 fake transport 验证：

| Gate | 断言 |
| --- | --- |
| RF-01 | object handler 收到本地 `R2Bucket`，raw stub 不可见 |
| RF-02 | default `WorkerEntrypoint` constructor 和 method 都看到 wrapped env |
| RF-03 | named `WorkerEntrypoint` 同样被包装，entrypoint name 不改变 |
| RF-04 | `head()` 返回对象的 `writeHttpMetadata()` 同步修改本地 Headers |
| RF-05 | `get()` 返回本地 stream，`bodyUsed` 和 helper 一次消费正确 |
| RF-06 | stream cancel 能到达 fake transport；不把断连当作唯一清理保证 |
| RF-07 | facade module collision、reserved env collision 和 wrapper tamper fail closed |
| RF-08 | `worker_code_sha256` 同时覆盖原 bundle、binding descriptor 和注入 source version |
| RF-09 | cold/warm load、promotion、rollback 和 workerd restart 都加载同一 facade version |
| RF-10 | tenant importable env、module import 和 property enumeration 无法取得 raw capability |

任一项失败都先修正 injection architecture，不能通过删 API 或把同步方法改成异步来绕过。

## 3. Cloudflare 常用 API 兼容面

以当前官方 [R2 Workers API reference](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)
和 [R2 limits](https://developers.cloudflare.com/r2/platform/limits/) 为语义基线。

### 3.1 Worker binding surface

```ts
interface R2Bucket {
  head(key: string): Promise<R2Object | null>
  get(key: string, options?: R2GetOptions): Promise<R2ObjectBody | R2Object | null>
  put(
    key: string,
    value: ReadableStream | ArrayBuffer | ArrayBufferView | string | null | Blob,
    options?: R2PutOptions
  ): Promise<R2Object | null>
  delete(key: string | string[]): Promise<void>
  list(options?: R2ListOptions): Promise<R2Objects>
}

type R2GetOptions = {
  onlyIf?: R2Conditional | Headers
  range?: { offset?: number; length?: number; suffix?: number } | Headers
}

type R2PutOptions = {
  onlyIf?: R2Conditional | Headers
  httpMetadata?: R2HTTPMetadata | Headers
  customMetadata?: Record<string, string>
  md5?: ArrayBuffer | string
  storageClass?: "Standard"
}
```

`R2Object` 暴露 `key`、`version`、`size`、`etag`、`httpEtag`、`uploaded`、`httpMetadata`、
`customMetadata`、`range`、`checksums`、`storageClass` 和同步 `writeHttpMetadata(headers)`。
`R2ObjectBody` 额外暴露 `body`、`bodyUsed`、`arrayBuffer()`、`bytes()`、`text()`、`json()` 和
`blob()`。

### 3.2 兼容矩阵

| 能力 | P0.5 | 说明 |
| --- | --- | --- |
| `head` | 支持 | missing 返回 `null` |
| `get` | 支持 | body 真正 streaming |
| `put` string/buffer/view/blob/stream/null | 支持 | bounded single-part |
| `delete` single/array | 支持 | array 最多 1000 keys |
| `list` prefix/cursor/delimiter/include | 支持 | provider lexicographic order |
| single range | 支持 | offset/length/suffix 或 Headers |
| conditional GET | 支持 | ETag 与 uploaded time |
| conditional PUT | 部分支持 | 只支持 provider 原子 ETag condition |
| HTTP metadata | 支持 | 六个常用字段 |
| custom metadata | 支持 | canonical JSON，见 metadata budget |
| `writeHttpMetadata` | 支持 | tenant isolate 内同步执行 |
| body helpers | 支持 | tenant isolate 内维护一次消费状态 |
| MD5 checksum | 支持 | staging 时计算；可校验调用方 MD5 |
| 其他 checksum | 不支持 | 不从 provider ETag 猜测 |
| `Standard` | 支持 | 其他 storage class 拒绝 |
| multipart | 不支持 | P0 非阻塞项 |
| SSE-C | 不支持 | 不让 tenant 提供额外 encryption key |

### 3.3 固定 limits

P0.5 capability V1 使用：

```rust
const R2_PROVIDER_KEY_MAX_BYTES: usize = 1024;
const R2_MAX_OBJECT_BYTES_DEFAULT: u64 = 512 * 1024 * 1024;
const R2_MAX_OBJECT_BYTES_HARD: u64 = 5 * 1024 * 1024 * 1024 - 5 * 1024 * 1024;
const R2_MAX_DELETE_KEYS: usize = 1000;
const R2_DEFAULT_LIST_LIMIT: u16 = 1000;
const R2_MAX_LIST_LIMIT: u16 = 1000;
const R2_MAX_CUSTOM_METADATA_JSON_BYTES: usize = 4 * 1024;
const R2_CURSOR_TTL_MS: u64 = 15 * 60 * 1000;
```

Cloudflare 允许 1024-byte object key，但本方案把 logical bucket 映射到同一个 physical S3 bucket，
physical prefix 也计入 provider key limit。默认：

```text
tenant/r2/v1/<36-byte-resource-id>/objects/<user-key>
```

固定部分是 58 bytes，因此默认可接受的 user key 上限是 966 UTF-8 bytes。实现必须按实际冻结的
`physical_prefix` 计算 `1024 - physical_object_prefix.len()`，不能先接受 1024 bytes 再让 provider
报错。这个较小上限是明确的兼容偏差；若未来要完整 1024-byte key，需要引入不可逆 key mapping
或 object catalog，不在 P0.5 偷偷增加。

默认 object 上限 512 MiB 是 SMB 单节点的 disk/concurrency policy，不是 provider 极限。operator
可以调高，但 hard ceiling 不超过 single-part provider 上限；提高前必须同时评估 local staging、
request deadline 和并发上传的最坏磁盘占用。

## 4. 与 Cloudflare 有意不同的语义

| Cloudflare R2 | 本方案 |
| --- | --- |
| 独立 physical bucket | 一个 provider bucket 下的 logical prefix |
| 1024-byte user key | 默认 966 bytes，按 physical prefix 动态计算 |
| object 最大约 4.995 TiB | P0.5 默认 512 MiB、single-part hard ceiling |
| metadata 最大 8192 bytes | custom metadata canonical JSON 默认 4 KiB，给 base64 envelope 与内部 header 留余量 |
| 全球强一致 | 单 provider；要求 provider 对 read/list/delete 提供强一致 |
| `InfrequentAccess` | 只支持 `Standard` |
| 所有 documented checksum | 只保证 MD5 |
| multipart | P0.5 不支持 |
| 原生 R2 binding object | project-owned local facade；不承诺 prototype/`instanceof` 完全一致 |

另外：

- `put({ onlyIf: { uploadedBefore/uploadedAfter } })` 返回 `R2_UNSUPPORTED_CONDITION`；不能用
  `HEAD + PUT` 模拟非原子的 date condition；
- cursor 15 分钟过期，跨 bucket/generation/options 使用返回 `R2_CURSOR_INVALID`；
- provider 不支持 required conditional PUT 时，R2 readiness 失败，而不是静默降级；
- `delete()` missing key 仍成功；
- 不暴露 provider request ID、XML body、endpoint、bucket 或 physical key；
- mutation timeout 可能是 `result-unknown`，不得向 tenant 声称一定失败。

## 5. S3 namespace 与 typed store

### 5.1 配置

在现有 `S3Config` 增加：

```toml
[s3]
prefix = "system/"
r2_prefix = "tenant/r2/"
```

静态验证要求：

- 两个 prefix 都是 relative、以 `/` 结尾、不含 `..`、反斜线和空 segment alias；
- `prefix` 与 `r2_prefix` 不能相等，也不能互为 prefix；
- system prefix 不能位于 `tenant/` 下；R2 prefix 默认且推荐位于 `tenant/r2/`；
- 已存在 resource 后不能直接修改 bucket/endpoint/system prefix/R2 prefix；迁移需要显式工具。

增加独立 `R2Config`：

```toml
[r2]
max_object_bytes = 536870912
max_concurrent_uploads = 4
max_concurrent_downloads = 16
max_staging_bytes = 2147483648
max_metadata_head_concurrency = 8
operation_timeout_ms = 30000
cursor_ttl_ms = 900000
```

### 5.2 不扩散 `ArtifactStore`

现有 `ArtifactStore` 是 `system/` 下的 immutable artifact/backup authority。P0.5 不能给它增加
任意 tenant key 方法。推荐拆出私有低层 client context，再暴露两个 compile-time typed store：

```text
S3ClientContext                 // client + physical bucket，crate-private raw access
├── ArtifactStore              // 只能构造 system keys
└── R2ObjectStore              // 只能构造 frozen logical bucket keys
```

service/backend 不能接收 raw physical key；只传 `R2BucketLocator + UserObjectKey`。所有 prefix 拼接、
provider key length 校验和错误脱敏都在 `R2ObjectStore` 内完成。

### 5.3 Physical layout

```text
tenant/r2/v1/<resource-id>/meta/identity.json
tenant/r2/v1/<resource-id>/objects/<raw-user-key>
```

`identity.json` 是小型 immutable marker，包含：

```json
{
  "schemaVersion": 1,
  "platformId": "...",
  "resourceId": "...",
  "createdAtMs": 0
}
```

user key 是允许为空的 string，并拒绝 exact `.`/`..` path segment；除此以外原样拼到
`objects/` 后面。`%2F`、`//` 和前导 `/` 都只是 S3 key 字符，不能先 percent decode，也不能做
filesystem 或 Unicode normalization。只有 UTF-8 编码和 S3 SigV4/HTTP 边界做一次必要 encoding。

## 6. Control plane schema

新增 `005_r2.sql`：

```sql
CREATE TABLE r2_buckets (
  resource_id            TEXT PRIMARY KEY REFERENCES resources(id),
  physical_prefix        TEXT NOT NULL UNIQUE,
  schema_version         INTEGER NOT NULL CHECK(schema_version >= 1),
  max_object_bytes       INTEGER NOT NULL CHECK(max_object_bytes > 0),
  provider_config_sha256 BLOB NOT NULL CHECK(length(provider_config_sha256) = 32),
  created_at_ms          INTEGER NOT NULL,
  delete_started_at_ms   INTEGER,
  last_probe_at_ms       INTEGER
) STRICT;
```

需要与 P0.4 同等级 trigger：

- insert 时 `resources.kind = 'r2_bucket' AND state = 'creating'`；
- `resource_id`、`physical_prefix`、`schema_version`、`max_object_bytes`、
  `provider_config_sha256`、`created_at_ms` 永久 immutable；
- `provider_config_sha256` 冻结 endpoint、region、physical bucket、path style、system prefix 和 R2
  prefix authority；配置漂移必须 fail closed；
- live resource 不能直接删除 product row；
- 只有物理 prefix 已清空且 marker 已删除，resource 才能 tombstone；
- tombstone 后删除 locator row，避免把它误当成可调用 resource。

不新增 `r2_objects` 表。list、head、quota 和 delete recovery 都以 S3 为准。

## 7. Bucket lifecycle

### 7.1 Create

1. P0.3 reserve `resources(state=creating)`；
2. 计算并插入 immutable `physical_prefix`；
3. 使用 `If-None-Match: *` PUT identity marker；
4. HEAD + GET marker，验证 schema/platform/resource；
5. 标记 resource ready；
6. lost response 由 `reconcile()` 读取同一 marker 收敛。

已存在但内容不匹配的 marker 是 `R2_PREFIX_COLLISION`，必须 fail closed。不能覆盖 marker 或换一个
prefix 继续创建。

### 7.2 Delete

默认删除遵循 physical bucket 的安全直觉：

- 先 list `objects/` limit 1；
- 非空且未显式 `force=true` 时返回 `R2_BUCKET_NOT_EMPTY`，resource 保持 ready；
- 空 bucket 才进入 P0.3 deleting fence。

强制删除：

1. 校验 referrer 为零并进入 deleting，拒绝新调用；
2. drain `ResourcePin`；
3. 每轮从 `objects/` 第一页开始 list，最多删除 1000 keys；
4. multi-delete 可用时使用 bounded batch；否则 bounded 并发逐个 delete；
5. restart 后重复步骤 3，删除是幂等的，不持久化 provider cursor；
6. 确认 objects prefix 为空；
7. 删除 identity marker；
8. 再次 HEAD marker/list objects，确认物理 identity 不可达；
9. tombstone resource。

不使用 continuation cursor 跨 delete batch，因为删除会改变 listing；反复读取第一页更容易恢复，
且不会把 provider token 当作 durability authority。

### 7.3 Rename 与同名重建

rename 只改 `resources.name`。physical prefix、resource ID 和旧 deployment binding 都不变。
删除后同名重建得到新 UUID 和新 prefix，旧 cursor、binding 和 S3 object 不能指向新 bucket。

## 8. Object metadata model

一次 PUT 生成随机 UUIDv7 `version`，并把以下 host metadata 随 object 原子写入：

```text
x-amz-meta-oc-r2-schema=1
x-amz-meta-oc-r2-version=<uuidv7>
x-amz-meta-oc-r2-custom=<base64url(canonical-json)>
x-amz-meta-oc-r2-md5=<hex>
```

HTTP metadata 使用 S3 标准 header：`Content-Type`、`Content-Language`、`Content-Disposition`、
`Content-Encoding`、`Cache-Control` 和 `Expires`。custom metadata 放入单个 canonical envelope，
避免 S3 provider 对 user metadata key 的大小写折叠、ASCII 限制和内部 key collision。

读取时必须验证 host metadata schema、version、canonical JSON 和大小。缺失/损坏的内部 metadata
返回 `R2_OBJECT_METADATA_INVALID`，只隔离该 object；不得猜默认 version 或把 raw provider metadata
直接暴露给 tenant。

`etag` 使用 provider 返回的 opaque ETag，`httpEtag` 做 RFC 合法 quoted form。MD5 来自 staging
时实际计算的 digest，绝不假设 ETag 就是 MD5。

## 9. Key 与 option canonicalization

### 9.1 User key

- 必须是 string；允许空 string，与 S3/R2 平面 key 模型一致；
- 拒绝 lone UTF-16 surrogate；
- 编码成 UTF-8 后执行动态 physical key budget；
- 不 trim、不 normalize、不 percent decode；
- 日志和 metrics 不记录 key；audit 只记录 keyed hash/长度。

### 9.2 Range

只接受三种形状：

- `{ offset, length? }`；
- `{ length }`，等价从 offset 0；
- `{ suffix }`。

`suffix` 不能与 offset/length 同时出现；所有值必须是非负 safe integer。Headers 只读取单个合法
`Range: bytes=...`，多 range 返回 `R2_RANGE_NOT_SUPPORTED`。unsatisfiable range 映射稳定错误，
不返回整 object。

### 9.3 Conditional

GET 支持：

- `etagMatches` / `If-Match`；
- `etagDoesNotMatch` / `If-None-Match`；
- `uploadedBefore` / `If-Unmodified-Since`；
- `uploadedAfter` / `If-Modified-Since`。

有 condition 的 GET 使用：

1. unconditional HEAD 获取一个 object version 的完整 metadata；
2. 在 host 侧按 R2 rule 计算 condition；失败直接返回无 body 的 metadata object；
3. 通过时用该 HEAD 的 exact ETag 做 conditional GET；
4. 若并发覆盖导致 precondition failure，最多重新读取一次，之后返回 retryable conflict。

这样能保证返回 body 与 metadata 属于同一版本，也不依赖 provider 在 304/412 中返回完整 metadata。

PUT 只把 ETag condition 原子下推到 provider。provider preflight 必须证明 `If-Match` 和
`If-None-Match` 行为；date condition 明确不支持。

## 10. Read path

### 10.1 `head`

1. P0.3 backend 重新授权并 pin resource；
2. 构造 typed physical key；
3. S3 HEAD；
4. 404 返回 `null`；
5. 验证 metadata，返回 transport DTO；
6. local facade 创建 `R2Object`。

### 10.2 `get`

无 condition 时直接 GET；有 condition 时使用上一节的 HEAD + conditional GET。body 作为 bounded
`ReadableStream<Uint8Array>` 穿过 backend、loader host 和 WorkerLoader JSRPC，不经 JSON/base64。

stream lifecycle：

- backend 在 headers/metadata 校验完成后才把 stream 交给 tenant；
- response body size 受 object metadata 和 requested range 双重上限；
- reader cancel 尽力 abort provider request 并释放 semaphore；
- wall timeout 和 byte limit 是最终保护，不依赖 client disconnect 一定传播；
- local body helper 使用同一 stream，并维护一次消费的 `bodyUsed`。

### 10.3 `list`

`prefix` 和 `delimiter` 先附加在 logical `objects/` prefix 后，再调用 `ListObjectsV2`。返回时：

- 严格剥离 exact physical object prefix；
- 任何不在 exact prefix 下的 provider result 都触发 protocol error；
- object 与 `delimitedPrefixes` 保持 provider lexicographic order；
- 未请求 `include` 时不做 HEAD，HTTP/custom metadata 返回空对象；
- 请求 include 时做 bounded HEAD fanout，并允许一页少于 limit；
- 单个 object metadata 损坏使本次 list 失败，不返回半真半假的 page。

cursor payload：

```json
{
  "v": 1,
  "resourceId": "...",
  "generation": 1,
  "prefixSha256": "...",
  "delimiterSha256": "...",
  "includeMask": 0,
  "providerToken": "...",
  "expiresAtMs": 0
}
```

payload 用 master-key-derived cursor key 做 HMAC。provider token 不直接暴露，也不写日志。

## 11. Write path

### 11.1 Secure staging

布局：

```text
data/r2-staging/<resource-id>/<request-uuid>
```

文件名只来自 typed resource ID 和 host request UUID，不来自 object key。创建使用 `O_EXCL`、0600、
no-follow 和 owned-path validation。

adapter 把 input 统一成 byte stream。backend 一边写 staging，一边：

- 计算 length 和 MD5；
- 检查 object limit、global staging budget 和 disk hard watermark；
- 检查可选 caller MD5；
- 在 failure/cancel 时关闭并删除 partial file。

staging 完成后才调用 S3 PUT，设置 exact content length。这样 SDK retry 可以安全重放同一 bytes，
不会要求 tenant stream 可重复读取。startup 在 single-owner 阶段清理旧 staging file。

### 11.2 Atomic provider PUT

S3 PUT 同时写 bytes、HTTP metadata、host metadata 和 condition。成功后使用返回值或 HEAD 验证：

- size；
- version metadata；
- MD5 metadata；
- ETag 存在且可 canonical quote。

验证失败返回 integrity error，不能伪造成功。response loss 后 object 可能已提交；同一 backend call
可以用同一 staging/version 做有限重试，但跨 tenant call 不自动重试 mutation。

### 11.3 `delete`

single delete 直接调用 DeleteObject。array delete：

- 先完整验证全部 keys，任何一个无效则一个都不发送；
- 最多 1000 keys；
- provider 支持 multi-delete 时使用一个 request；
- 不支持时 bounded 并发逐个 delete；
- missing key 视为成功；
- response loss 返回 `R2_RESULT_UNKNOWN`，不声称全部未删除。

## 12. Provider capability preflight

P0.1 的 canary 只验证基本 PUT/HEAD/GET/DELETE。P0.5 增加 R2 full preflight，使用 tenant preflight
专用随机 prefix，验证：

1. exact arbitrary key encoding，包括空格、`+`、`%`、Unicode、`//`；
2. HTTP/custom host metadata roundtrip；
3. Range GET；
4. `If-None-Match: *` 和 `If-Match` atomic PUT；
5. read-after-write、overwrite、delete-after-read；
6. ListObjectsV2 prefix、delimiter、lexicographic order 和 continuation token；
7. list-after-write/list-after-delete；
8. multi-delete capability，标记为 optional；
9. error body/status 可被安全分类且不会泄漏到 tenant。

required capability 失败时 `/health/ready` 对 R2 标记 unavailable，并让 `doctor --full` 失败。由于
bundle/artifact 也依赖同一 provider，auth/connectivity failure 仍影响整个平台 readiness；只有
R2-specific optional multi-delete 缺失可以降级。

单次 preflight 不能数学证明 provider 永远强一致，因此文档和 doctor 必须明确：operator 选择的
provider 承担 consistency/durability authority，平台只验证当前可观察能力。

## 13. Adapter 与 private protocol

### 13.1 Raw transport

loader host 新增静态 `R2Transport extends WorkerEntrypoint`。它只暴露 flat terminal methods：

```text
head(key)
get(key, options) -> { meta, body? }
put(key, bodyStream, options) -> meta | null
delete(keys)
list(options) -> page DTO
```

trusted props 沿用 P0.3：`bindingId`、`deploymentId`、`descriptorSha256`、
`resourceSpecGeneration` 和 read/write permissions。tenant 不能提交 resource ID 覆盖它们。

### 13.2 Local facade

injected `R2Bucket`：

- 做 JS type、Headers、Date、BufferSource、metadata 和 option normalization；
- 把 Blob/stream 变成 byte stream，但不 buffer；
- terminal call 才调用 raw transport；
- 将 DTO 转为 local `R2Object`/`R2ObjectBody`；
- 用 WeakMap/private fields 保存 raw stub，避免简单 property enumeration 暴露它。

backend 仍需重复验证所有 length/type/option，不信任 facade。facade 是 API compatibility layer，
不是 authorization boundary。

### 13.3 HTTP/frame boundary

loader host 到 Rust backend 沿用 authenticated private binding service，但为 R2 定义独立 content
type 和 endpoint family：

```text
/internal/bindings/v1/r2/<binding-id>/head
/internal/bindings/v1/r2/<binding-id>/get
/internal/bindings/v1/r2/<binding-id>/put
/internal/bindings/v1/r2/<binding-id>/delete
/internal/bindings/v1/r2/<binding-id>/list
```

metadata frame 有固定上限，body 使用 stream。不要把 object bytes 包进 JSON。

## 14. Concurrency、timeout 与 backpressure

全局和 per-bucket 分别限制：

- active upload；
- active download stream；
- metadata HEAD fanout；
- force-delete worker；
- staging bytes。

获取顺序固定为 global -> bucket -> operation-specific，避免 semaphore inversion。S3 SDK request
timeout、platform operation timeout 和 stream idle timeout 是不同 budget；错误必须区分 connect、
headers、body 和 staging 阶段。

下载只在 consumer 拉取时读取 provider body。上传 staging writer 的速度由 disk write 和 JS stream
共同 backpressure。达到 hard disk watermark 后拒绝新 PUT，但 head/get/delete/list 继续工作。

## 15. Failure 与 result-unknown

| Failure point | 行为 |
| --- | --- |
| staging 前失败 | 无远端 mutation |
| staging 中失败 | 删除 partial file，无远端 mutation |
| conditional PUT 412 | 返回 `null`，无 mutation |
| PUT request 明确 4xx | 稳定 non-retryable error |
| PUT timeout/connection reset | `R2_RESULT_UNKNOWN`；object 可能已提交 |
| DELETE timeout | `R2_RESULT_UNKNOWN`；部分/全部 key 可能已删除 |
| GET body 中断 | stream error；不影响 object authority |
| list token invalid | `R2_CURSOR_INVALID`，不自动从头开始 |
| metadata corrupt | object-local integrity error |
| provider auth/permission | R2 unavailable，secret-safe operator error |

只对确定幂等的 read/list 和同一 backend operation 内、同一 staged payload 的 retry 使用 SDK retry。
不能把 mutation timeout 映射成普通 `R2_INTERNAL` 后让上层无条件重试。

## 16. Control API

P0.5 提供本平台最小管理面：

```text
POST   /v1/accounts/:account/r2/buckets
GET    /v1/accounts/:account/r2/buckets
GET    /v1/accounts/:account/r2/buckets/:resource
PATCH  /v1/accounts/:account/r2/buckets/:resource
DELETE /v1/accounts/:account/r2/buckets/:resource?force=false
```

create/delete 使用 P0.3 idempotency contract。API 永不返回 physical prefix、provider bucket、endpoint
或 provider token。可返回 logical name、resource ID、state、availability、created time 和 frozen
limits。

P0.5 不提供 public object management REST API。测试和 doctor 通过 trusted internal controller 调用
typed store；若未来提供 CLI object commands，必须独立定义 auth/audit/streaming contract。

## 17. Error mapping

建议稳定错误：

| Code | Retryable | 说明 |
| --- | --- | --- |
| `R2_KEY_INVALID` | 否 | key type/UTF-8/shape 非法 |
| `R2_KEY_TOO_LARGE` | 否 | 超出动态 physical key budget |
| `R2_INVALID_OPTIONS` | 否 | range/condition/metadata 非法 |
| `R2_UNSUPPORTED_CONDITION` | 否 | P0.5 不支持的 write date condition |
| `R2_UNSUPPORTED_FEATURE` | 否 | multipart/SSE-C/storage class 等 |
| `R2_OBJECT_TOO_LARGE` | 否 | 超出 frozen object limit |
| `R2_METADATA_TOO_LARGE` | 否 | metadata 超限 |
| `R2_CURSOR_INVALID` | 否 | cursor tamper/过期/参数不匹配 |
| `R2_BUCKET_NOT_EMPTY` | 否 | 非 force 删除 non-empty bucket |
| `R2_PRECONDITION_FAILED` | 否 | transport 内部 condition failure；facade 转成 null/object |
| `R2_OVERLOADED` | 是 | semaphore/staging budget 饱和 |
| `R2_PROVIDER_UNAVAILABLE` | 是 | timeout/5xx/connectivity |
| `R2_RESULT_UNKNOWN` | 是但需幂等判断 | mutation 结果未知 |
| `R2_OBJECT_METADATA_INVALID` | 否 | 单 object metadata 损坏 |
| `R2_PREFIX_COLLISION` | 否 | identity marker 不匹配 |

tenant message 不包含 raw S3 XML、request URL、bucket、prefix、credential、filesystem staging path 或
SDK debug chain。operator log 使用 error category/stage/status，object key 只记录 keyed hash。

## 18. Observability 与 health

低基数 metrics：

```text
r2_operations_total{operation,outcome}
r2_operation_duration_seconds{operation,stage}
r2_bytes_total{direction}
r2_active_streams{direction}
r2_staging_bytes
r2_provider_errors_total{stage,category}
r2_condition_failures_total{operation}
r2_list_head_fanout_total
r2_result_unknown_total{operation}
r2_force_delete_remaining_batches
```

禁止 label：account、resource、binding、key、ETag、cursor、provider request ID。

resource health：

- marker/普通 object metadata 损坏只影响对应 bucket/object；
- provider-wide auth/connectivity failure 使所有 R2 resource unavailable；
- transient 5xx 先运行时返回 retryable error，持续超过 debounce 才持久化 degraded；
- health 恢复必须由成功 probe 驱动，不能只因计时器到期自动 healthy。

## 21. P0.5 Exit Gate

1. P0.5.0 RF-01 至 RF-10 连续三轮 fresh stock-workerd 通过；
