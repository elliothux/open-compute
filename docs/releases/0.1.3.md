# open-compute 0.1.3

0.1.3 adds a project-native Wrangler workflow for teams running Cloudflare-compatible Workers on a self-hosted open-compute instance. A repository can now keep an ordinary `wrangler.jsonc`, select a named open-compute target, and use pinned Wrangler commands without copying control-plane URLs or credentials into project files.

This release is intended for individual operators and small teams that want familiar Wrangler project commands while keeping one `ocd` process as the local authority for deployment, resources, routing, and runtime lifecycle.

## What's new

- `ocd target add`, `list`, `show`, `use`, and `remove` manage validated local or remote project targets. Target records live outside the project and secret material is never written to `wrangler.jsonc`.
- `ocd wrangler -- <command>` launches the repository-pinned Wrangler version with target-scoped Cloudflare API configuration. Deploy, versions, rollback, tail, secret, KV, D1, R2, Queues, Vectorize, Workflows, and AI commands use the same persisted `ocd` authority.
- The project toolchain now treats Wrangler as the single deployment surface. The former private `oc deploy` wrapper and its compatibility tests have been removed under the Day 1 model.
- The bundled example includes a current `wrangler.jsonc`, an exact Wrangler pin, and GitHub Actions and GitLab CI templates that invoke `ocd wrangler`.
- English and Chinese documentation now describe project setup, target selection, secrets, routing, versions, rollback, and CI usage through the same workflow.

## Fixed

- Service Binding WebSocket handoff now preserves the upgraded connection path instead of losing the runtime response during proxying.
- Runtime event contexts expose the supported capability surface consistently.
- Dashboard imports use filename casing that works on Linux case-sensitive filesystems.
- Dashboard operator sign-in no longer crashes with a React update-depth loop after the jotai toast-sink refactor; packaged Dashboard e2e exercises the embedded SPA again.
- Instance control sockets keep a bounded path when the host provides a long temporary-directory path.
- Release validation reads version notes from the authoritative `docs/releases/` directory.
- Python Dynamic Workers on the certified compatibility date use a formally pinned Pyodide bundle embedded as gzip in the single `ocd` executable. Runtime materialization verifies both archive and bundle digests before workerd loads the local private cache.
- The single certified Workers compatibility date advances to `2026-09-08`, selecting Pyodide `314.0.6` for Python Workers without a legacy runtime branch.

## Before you upgrade

- No database reset, data migration, or configuration rewrite is required when upgrading from 0.1.2.
- The old `oc deploy` toolchain command is intentionally gone. Update scripts to use `ocd wrangler -- deploy` and keep an exact Wrangler version in the project.
- Existing `ocd` instances continue to own their current configuration and data directories. Add a named target explicitly for each project that should use the new workflow.
- Target selection fails closed when configuration is absent, ambiguous, malformed, or points at an account that does not match the selected instance.
- open-compute remains pre-1.0; obsolete local development interfaces are removed directly rather than carried as compatibility aliases.

After replacement, verify the installation with:

```console
ocd --version
ocd config check
ocd doctor
ocd target list
```

## Install or upgrade

For a new installation or an existing receipt-managed installation, download and review the installer, then pin this release explicitly:

```console
curl -fsSL -o install.sh https://raw.githubusercontent.com/elliothux/open-compute/v0.1.3/scripts/install.sh
OPEN_COMPUTE_RELEASE_TAG=v0.1.3 sh install.sh
ocd setup --yes
```

In a Worker project, install the exact Wrangler version declared by the project and select the target before running project commands:

```console
ocd target add local --instance default
ocd target use local
ocd wrangler -- deploy
```

The installer verifies `release.json` and `SHA256SUMS`, refuses to replace a binary it does not own, and does not modify workload data.

## Security

There are no published security advisories specific to 0.1.3. Target configuration keeps credentials out of repository files, validates account and endpoint identity at the authority boundary, and does not expose internal runtime tokens to Wrangler or tenant code.

## Known limitations

- Wrangler must be installed and pinned by the project; `ocd` does not download it or fall back to a global installation.
- `wrangler dev --remote`, automatic upload preservation, managed CI, and percentage rollouts are not implemented.
- A Wrangler environment provides project naming and resource isolation, not an independent data directory, listener, object authority, or failure domain. Use a different instance and target when those boundaries are required.
- Code signing and macOS notarization are not included in 0.1.3.
- Hosted Cloudflare differential testing, broad third-party application qualification, and long-running soak tests remain separate from release qualification.
