Open Compute 0.4.0 adds Container execution and snapshot paths for single-machine deployments.
Publication requires every revision-bound release qualification job to pass.

## What's new

- The implementation adds an operator-owned Container Broker and immutable Container targets.
  Code-only deployment keeps the current execution.
  Image or resource deployment creates a new target and retires the previous execution.
- Durable Object containers gain process lifecycle, HTTP and WebSocket transport, exec streams, named images, inactivity policy and snapshot code paths.
  The local product cases exercise these paths with real workerd, Docker and SQLite.
- Snapshot capture retains filesystem data and excludes volatile `/run` data.
  Snapshot restore creates a new execution from the retained image.
  Artifact ownership and bounded cleanup remain explicit.

## Fixed

- The private KV backend closes HTTP/1 connections when it rejects a streaming PUT with unread upload bytes.
  Value limits and permission checks remain unchanged.
- Exec output collection retains its native process handle until collection completes.
  The handle preserves late stdout and stderr when garbage collection occurs.
- Runtime host modules import the public WebSocket wire helpers without importing the private RPC issuer.
  Native private modules remain outside the tenant module graph.
- Durable Object alarm setup accepts callable RPC views whose methods are available through property access.
  The runtime still checks each required method.
- Container class acquisition and deletion share an ordered transition.
  Concurrent route changes revoke the previous grant before a replacement grant becomes current.
  Tenant execution remains outside this transition.
- HTTP and WebSocket callbacks retain their original owner and Container lease.
  Completion from an old execution cannot complete a replacement execution.
- Snapshot control enters a fresh native event under the original owner.
  Source image verification, archive publication and materialization retain their checks and failure boundaries.

- Repeating service start preserves an already running launchd process.
  An explicit restart still replaces the process.
- Browser Run waits for the real CDP context before attaching after restart.
  The real-browser regression retains its original assertions.

## Before you upgrade

Back up the selected persistent data root before an upgrade.
Control migrations V16 and V17 add Container and snapshot state.
Control migration V18 adds Directory snapshot authority.
The candidate retains all published migration bytes.

The Container declarations change the immutable Worker descriptor contract.
The local repair raises the loader schema to 2 and rejects retained executable versions with an older schema before binary replacement.
On 2026-10-20 UTC, the native five-OS installation matrix passed all ten user/system scopes.
The candidate correctly rejected the incompatible 0.3.0 upgrade and preserved the previous installation.
These checks do not establish a successful incompatible in-place upgrade or formal tag qualification.
For an incompatible instance, use a separate fresh installation, explicit data transfer and redeployment.
Do not rewrite stored Worker descriptors or migration records to bypass preflight.

For rollback, retain a backup made with the previous binary.
Do not remove migration rows or edit SQLite files to force a downgrade.
Stop the daemon before you replace its executable or restore its persistent data.

Container execution requires a separately operated Broker and a qualified rootful Linux Docker Engine.
The Broker checks overlay2, cgroup v2, seccomp, resource limits, the exec helper and snapshot behavior.
An installed Docker CLI does not prove these conditions.
The daemon does not install or start the Engine during startup.

## Install or upgrade

After the project publishes 0.4.0, back up the selected data root.
For an existing receipt-managed installation that passes preflight, run:

```console
ocd upgrade 0.4.0
```

For a separate fresh user-owned installation, download and review the versioned installer:

```console
curl -fsSL -o install.sh https://raw.githubusercontent.com/elliothux/open-compute/v0.4.0/scripts/install.sh
less install.sh
OPEN_COMPUTE_RELEASE_TAG=v0.4.0 sh install.sh
ocd setup --yes
```

Before admitting traffic, check `ocd --version`, `ocd config check`, `ocd instances`, `ocd doctor` and `ocd capabilities --json`.
Use the reported capability status when selecting products.

## Security

The Broker owns the Docker socket and an authenticated private Unix socket.
Tenant bindings do not expose the Docker socket, host credentials or generation tokens.
Public Durable Object and Service binding checks remain in the Container transport path.
Production startup remains offline.

The platform retains one shared outbound IP capability.
The capability permits host-allowed public, private, loopback and metadata IP traffic.
Unix sockets remain denied to tenant outbound APIs.
Operators own host network filtering; the platform does not claim isolation between Worker or instance networks.

## Known limitations

- The local Container API retains all 65 stable members and includes directory backup restoration.
  Upstream [PR #7123](https://github.com/cloudflare/workerd/pull/7123) keeps `snapshotDirectory()` behind the experimental flag.
  The nine stable Directory members use the documented local capture and restore paths.
  Local implementation and restore evidence do not establish a hosted stable directory snapshot producer.
- Two snapshot behaviors use the accepted upstream direction, rather than reproducing every retained hosted observation.
  `snapshotContainer()` accepts omitted options, as specified by the fixed types and upstream [PR #7453](https://github.com/cloudflare/workerd/pull/7453).
  A restored container returns an empty `inspect().image`, as explained in the official [documentation change #33825](https://github.com/cloudflare/cloudflare-docs/pull/33825).
  The managed registry reference observed after hosted restore has no established mapping to the original image.
  The Cloudflare-managed image-size formula remains unknown.
- Local custom resources do not establish hosted input compatibility.
  The local product case uses `0.03125` vCPU, `128` MiB memory and `1000` MB disk and checks SQLite and Engine resource settings.
  On 2026-10-21 UTC, hosted readiness failed for that profile and for separate CPU-only and memory-only reductions.
  Two `1` vCPU, `3072` MiB, `4000` MB controls started successfully before and after those probes.
  The single-field probes kept the control values for the other two resources.
  These observations do not establish the managed predicate, exact limits or actual allocation.
- The signal 34 observation covers 12.225 seconds, not permanent signal suppression.
  This measurement belongs to the controlled hosted comparison recorded on 2026-10-13.
- The platform remains single-machine and self-hosted.
  Cloudflare multi-region placement, Sandbox and excluded managed products remain outside the declared scope.
  Code signing and macOS notarization are not included.
