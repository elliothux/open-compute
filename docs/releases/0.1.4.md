# open-compute 0.1.4

0.1.4 adds a complete Cloudflare Artifacts implementation for self-hosted open-compute installations. Operators can create namespaces and repositories, use Wrangler and Worker bindings, push and clone through Git Smart HTTP, and include repository data in the existing snapshot and restore lifecycle.

This release is intended for single-machine operators who need Cloudflare-compatible source artifact storage without adding a separate Git service or hosted control plane.

## What's new

- Cloudflare Artifacts namespaces, repositories, public HTTPS imports, independent forks, and read/write repository tokens are persisted by the existing `ocd` authority.
- The Cloudflare v4 REST surface supports namespace, repository, token, commit, tree, blob, file, raw content, and log operations with bounded pagination and stable errors.
- Git Smart HTTP supports upload-pack protocol v1/v2 and receive-pack v1. Repository paths use opaque identities rather than account-controlled names.
- The pinned Wrangler 4.127.1 Artifacts commands and the pinned Worker `Artifacts` binding share the same immutable Version binding and authorization model.
- Artifact repository files participate in authenticated platform snapshots, restores, restart reconciliation, disk-pressure admission, quotas, and bounded lease draining.

## Fixed

- `scripts/install.sh` now checks both the binary and install-receipt directories before making any release network request. An unwritable system prefix reports exact system-wide and per-user commands instead of downloading assets and then exposing a raw `mkdir` failure.
- The Dashboard login toast sink no longer passes a function through Jotai's updater semantics, avoiding a render update-depth loop after sign-in.
- Linux ARM64 Dashboard qualification uses the repository-local Playwright Chromium executable, and runtime/Wrangler tests use bounded paths and stricter success assertions across supported hosts.

## Before you upgrade

- Upgrading from 0.1.3 does not require a database reset or configuration rewrite. Startup transactionally applies the new immutable migration 018 for Artifacts metadata.
- Existing Worker deployments, resources, snapshots, configuration, secrets, and object authority remain in place. New Artifact repositories consume the configured data-dir and snapshot capacity.
- Remote Git clients require `[artifacts].public_origin` to be the exact operator-owned HTTP(S) origin they can reach. The loopback default is suitable only for clients on the same host.
- Public repository import deliberately accepts HTTPS without credentials and rejects redirects, proxies, private or metadata addresses, and DNS rebinding targets. Private remote import, SSH, Git LFS, mirrors, ArtifactFS, and event subscriptions are not implemented.
- open-compute remains pre-1.0 and uses one current Day1 model; no obsolete Artifacts schema, API, or storage compatibility path is retained.

After replacement, verify the installation with:

```console
ocd --version
ocd config check
ocd doctor
ocd target list
```

## Install or upgrade

An existing receipt-managed installation can upgrade directly:

```console
ocd upgrade 0.1.4
```

For a new system-wide installation, download and review the installer before elevating it:

```console
curl -fsSL -o install.sh https://raw.githubusercontent.com/elliothux/open-compute/v0.1.4/scripts/install.sh
less install.sh
sudo env OPEN_COMPUTE_RELEASE_TAG=v0.1.4 sh install.sh
sudo /usr/local/bin/ocd setup --yes
```

For a user-owned project installation without a system service, use `OPEN_COMPUTE_INSTALL_PREFIX="$HOME/.local" sh install.sh` instead. The binary and receipt remain under that one prefix.

## Security

There are no published security advisories specific to 0.1.4. Artifact tokens are shown once and persisted only as installation-key digests with scope, expiry, revocation, and repository-generation checks. Git upload accepts only advertised object wants, receive-pack validates bounded commands and refs before pack processing, and public imports fail closed against private-network access. Tenant errors do not expose repository paths, Git stderr, token digests, credentials, or internal topology.

## Known limitations

- Artifacts use one machine's bare Git repositories and SQLite metadata authority. The release does not claim Cloudflare's hosted placement, replication, billing, account-wide quotas, or service request-rate topology.
- ArtifactFS, event subscriptions, automatic build/deploy, Git LFS, SSH, private remote import, and mirrors are outside the current supported surface.
- Wrangler must be installed at the exact project pin. `wrangler dev --remote`, managed CI, automatic upload preservation, and percentage rollouts remain unsupported.
- Code signing and macOS notarization are not included.
