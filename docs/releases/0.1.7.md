0.1.7 makes installation and instance removal safer for single-machine operators, makes upgrades and stops report a trustworthy completed state, and prevents document-parser failures from retrying forever. It also reorganizes the English and Chinese documentation around product, development, and operations tasks.

This release is intended for operators who want user-scoped installation by default, explicit data-retention boundaries during uninstall or purge, and bounded AI Search document-processing failures.

## What's new

- Non-root installation now defaults to `$HOME/.local`, while root installation alone defaults to `/usr/local`. `ocd setup --yes` creates host-standard user configuration and data roots plus a login-scoped systemd user unit or LaunchAgent; `setup --system` remains the explicit machine-wide path.
- `ocd instance unregister` removes service registration without deleting data. `ocd purge` and `ocd uninstall --purge` resolve and display the complete destructive plan, require exact path-bound confirmation, and retain S3-backed object data.
- The instance registry records the owning executable, configuration checksum, data path, and non-secret object authority. Purge validates those identities and refuses unsafe roots, changed configuration, symlinks, overlapping registrations, live sockets, and ambiguous ownership.
- The documentation site now groups material by products, development, operations, and reference, with matching English and Chinese navigation, local search, mobile language selection, and clearer Worker language guides.

## Fixed

- `ocd upgrade` now validates every active owned registration before replacing the binary, reports exact recovery commands for invalid registrations, and leaves stopped registrations stopped without requiring their configuration to remain loadable.
- `ocd stop` waits for the service manager, control socket, and platform data lock to agree that the instance is offline. macOS uses launchd session `bootout`, and a later start bootstraps an unloaded plist before kickstart.
- Xberg/Tesseract OCR result caching is explicitly disabled while the parser keeps its production file-size limit. The instance-owned AI Search parse cache is the only reusable parsed-document cache.
- Parser child exits, signals, I/O failures, timeouts, and output-limit failures now produce bounded sanitized diagnostics. Deterministic failures stop immediately; transient failures stop after five durable attempts and retain their stable error code across restart.
- Linux setup tests satisfy the release CI source-policy checks.

## Before you upgrade

- The instance registry uses the new schema 2 Day1 model. Earlier development registry records are intentionally rejected rather than upgraded. Remove the old local registry data and run setup again for those instances before relying on instance lifecycle commands.
- `instance remove` no longer exists; use `ocd instance unregister` to retain data or `ocd purge` for explicit local-data deletion. There is no compatibility alias.
- Existing AI Search parser-cache entries are not reused because the parser contract digest changed. Documents are recomputed under the new cache policy as work is indexed; no manual cache conversion is provided.
- Published platform database migrations are unchanged. Existing Workers, KV, R2, D1, Durable Objects, Queues, Workflows, routes, secrets, and immutable deployment artifacts require no migration for this release.

After replacing the binary and completing any required instance setup, verify the installation with:

```console
ocd --version
ocd config check
ocd doctor
ocd target list
```

## Install or upgrade

An existing receipt-managed installation can upgrade directly:

```console
ocd upgrade 0.1.7
```

For a new system-wide installation, download and review the installer before elevating it:

```console
curl -fsSL -o install.sh https://raw.githubusercontent.com/elliothux/open-compute/v0.1.7/scripts/install.sh
less install.sh
sudo env OPEN_COMPUTE_RELEASE_TAG=v0.1.7 sh install.sh
sudo /usr/local/bin/ocd setup --yes --system
```

For the default user-owned installation, run the reviewed installer without `sudo`, then run `ocd setup --yes`. The binary and receipt are stored below `$HOME/.local`; configuration and data use the host-standard user directories.

## Security

There are no published security advisories specific to 0.1.7. Destructive lifecycle commands now bind confirmation to the resolved paths and validate executable, configuration, data-root, socket, and object-authority ownership before mutation. Parser diagnostics expose only bounded classifications, exit or signal identity, byte counts, and a stderr digest; raw document data, stderr, paths, credentials, and secrets are not logged.

## Known limitations

- The native macOS document parser still has no enforceable hard memory limit. CPU, input/output, concurrency, timeout, disposable-directory, and cache controls remain active.
- macOS Developer ID signing and Apple notarization are planned but are not enabled for this release. Windows and Intel macOS remain source-build-only targets.
- AI Search remains a bounded single-machine implementation and does not claim Cloudflare hosted placement, global indexing throughput, managed connectors, fleet coordination, or billing behavior.
