0.2.0 adds operator-owned native extensions that user Workers call through ordinary Service Bindings, and it ships the matching pinned workerd that brokers those sessions. It is for single-machine operators who need a trusted local Provider beside the existing Cloudflare-compatible Worker model, and who can take a clean data directory through the V7 Service-descriptor break.

## What's new

- **User-extensible native bindings.** An operator lists `[extensions.<name>]` directories in the `ocd` config. Each directory is a strict `extension.toml` with one facade Worker and one native Provider. User Workers bind with Wrangler `services` and `props`; there is no new public Binding type. Only the facade receives `HOST.call` / `HOST.stream`. `ocd` loads extensions at startup, shares the Worker service namespace, and does not install, download, version, hot-reload, or sandbox tenant native code.
- **Direct Provider sessions.** workerd proves a session with `OCH1` and `SCM_RIGHTS`; `ocd` attaches `OCP1` to the Provider, waits for ACK, and then steps out. Business bytes travel on a Cap'n Proto `HostExtension` socket between workerd and the Provider. Documentation is a first-class [Extension](https://open-compute.dev/docs/extension/) topic beside Start, Operate, Products, and Reference.
- **Pinned workerd W3.** The formal runtime pin moves to `v1.20260918.1-open-compute-w3.40937077`. The fork adds the private `HostExtensionFactory` / `HostExtensionPort`, generation broker fd 4, Standard ResourceLimits for dynamic Workers, and delegated Worker Loader accounting. Formal FD passing uses `--//:io_backend=cxx`.

## SDK

- Package: `@open-compute/sdk@0.2.0`, published to the [npm registry](https://www.npmjs.com/package/@open-compute/sdk); install with `npm install @open-compute/sdk@0.2.0`.
- Pins: official `cloudflare@7.1.0`, Cloudflare OpenAPI revision `b8687f42e28fbfcb296a350f7dbf16349ea900af`, and Wrangler `4.127.1`.
- Surface: 141 official operations, 18 observed-standard Artifacts operations, and 21 open-compute extension operations. Standard calls retain official transport, authentication, retry, pagination, multipart, download, and `APIError` behavior. This release does not add SDK routes for native extensions; those remain operator config plus Wrangler `services`.
- Pairing: only an `ocd` and SDK with the same stable `X.Y.Z` are qualified together.

## Fixed

- A host child that overflows its bounded stderr is now stopped and reaped with the rest of its process group instead of leaving a live process after the owner has already failed the stream.

## Before you upgrade

- Stop `ocd` and take a current snapshot before replacing the binary.
- Control migration V7 is a Day1 break. If the data directory still has schema 1 `version_services` rows, startup fails atomically and requires a clean data directory. There is no backfill or dual read path. Published V1–V6 bytes are unchanged.
- After a successful V7 start, Service descriptors store either a stable Worker ID or a lowercase extension slug. Existing deployments pin the extension name, entrypoint, and canonical props, not the extension file bytes. Replacing those files and restarting `ocd` makes current deployments use the new implementation.
- Extension names share the live Worker service namespace. A collision with a Worker name fails closed at startup, Worker create, or Service upload. Removing an extension does not fall back to a Worker of the same name.
- `.localhost` Worker origins, secret references, and the Local versus S3 storage choice are unchanged from 0.1.10.

## Install or upgrade

An existing receipt-managed installation can upgrade directly:

```console
ocd upgrade 0.2.0
```

For a new user-owned installation, download and review the installer, then pin this release:

```console
curl -fsSL -o install.sh https://raw.githubusercontent.com/elliothux/open-compute/v0.2.0/scripts/install.sh
less install.sh
OPEN_COMPUTE_RELEASE_TAG=v0.2.0 sh install.sh
ocd setup --yes
```

Verify with `ocd --version`, `ocd config check`, `ocd doctor`, and `ocd capabilities --json`.

## Security

There are no published security advisories specific to 0.2.0. Extension session identity, Provider paths, raw file descriptors, and platform tokens stay out of tenant `env`, argv, and logs. `ocd` does not proxy business payloads after the session FD is handed over. Host children still receive a cleared environment and a verified executable identity.

## Known limitations

- Native extensions are an open-compute superset. Cloudflare hosted Workers do not provide `HOST`, OCH1/OCP1, or operator Provider processes.
- Day1 does not install, download, version, hot-reload, grant, marketplace, pool, HTTP-fallback, or OS-sandbox extensions. The operator owns host filesystem permissions and Provider compatibility.
- Optional macOS XPC qualification is not a cross-platform completion condition.
- `.localhost` endpoints are reachable only through a loopback-bound public listener and are not production HTTPS origins.
- The macOS document parser still has no enforceable hard memory ceiling; concurrency, input/output, CPU, and timeout bounds remain active.
- Code signing and macOS notarization are not included.
